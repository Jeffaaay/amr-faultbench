# 六类故障与编号对应（待审查）

只保留原计划的六类。补充文字把启动延迟列为 F1，把反馈丢失列为 F2；同一文字的首个实验却叫 F01_TPDO_DROPOUT。为避免执行错故障，当前文档优先使用完整语义名称。以下规范编号是草案，10/25 审查后再冻结。

| 建议规范 ID | 故障 | 补充文字的列表编号 |
| --- | --- | --- |
| F01_TPDO_DROPOUT | TPDO 丢失或过期 | F2 |
| F02_STARTUP_DELAY | 电机驱动上电延迟 | F1 |
| F03_SDO_TIMEOUT | SDO 回复超时 | F3 |
| F04_DRIVE_FAULT | EMCY / DS402 FAULT | F4 |
| F05_LOCALIZATION_STALE | 定位数据过期 | F5 |
| F06_DOCKING_INFEASIBLE | 对接路径不可行 | F6 |

首个实验保持用户明确指定的 F01_TPDO_DROPOUT。以后解析器不应接受有歧义的 F1/F2 别名。EMCY 报文和 DS402 FAULT 是不同可观测量，F04 的场景清单要分别写出触发与判定，不能假定二者总是同时出现。

11/2–8 扩展六类。开发集/隐藏集尚未冻结：“列表 F1–F4 开发、F5–F6 隐藏”只是用户给的待审查例子。正式划分前先检查技能可达性与可比性，再隔离故障类型、种子和参数组合；不能把本公开草案当成隐藏测试内容。
