# 恢复策略能做什么

状态：接口契约草案，不是已实现的机器人 API。

恢复的目标是正确诊断、等待证据并决定是否申请恢复。必要的安全停止本身不是失败，不能通过放宽阈值提高分数。

| 技能 | 能做的事 | 必须返回的证据 |
| --- | --- | --- |
| check_drive_state | 读取双侧驱动状态 | 节点、时间、新鲜度、状态或 unknown |
| wait_for_fresh_feedback | 有界等待新的双侧反馈 | 是否新鲜、是否成对、超时原因 |
| inspect_emcy | 读故障记录 | 原始故障标识、来源；无记录不等于无故障 |
| request_authorized_reset | 申请受互锁约束的复位 | 授权来源、请求/拒绝/完成状态，不能自行生成授权 |
| return_to_idle | 在既有安全条件满足时返回空闲 | 实际状态转换与确认，不自动恢复非零运动 |

推荐图的语义：发现故障 → 保持限制态 → 检查双侧状态 → 等待有效反馈 → 核实互锁和授权 → 申请复位 → 等待确认 → 空闲。每一步均有超时、unknown 和拒绝分支；失败回到安全等待/人工处理。

Agent 只编辑 policies 的明确白名单；不能写安全阈值、固件、硬件适配器、evaluator、隐藏测试、B0 人工基线或授权记录。运行器要使用文件权限/独立进程落实这一点，提示词约束不能算隔离已经实现。

复位后再运动需要新的明确任务许可。仅仅“CAN 发送成功”或“收到了 ACK”不足以证明驱动完成复位、整车停稳或任务成功。
